# 司会者・投影画面の同期抽選

抽選はサーバーで一度だけ受理し、全ホスト・投影に同じ抽選 ID と開始・公開・終了時刻を配信する。開始前に 200ms の配信余裕を設け、高速 1440ms、減速 1620ms、溜め 450ms、結果強調 650ms（演出 4160ms、受理からロック解除まで約 4360ms）で進行する。

結果はサーバーのタイマーで公開するまでクロージャー内に保持する。公開前は履歴、最新番号、カード判定、当選判定、CSV に追加しない。クライアントの回転番号は装飾であり、結果を決めない。複数ホストの連打は共有ロックで拒否する。

端末時計の差は Socket.IO の往復時間から補正し、その後は単調増加時計を使用する。ネットワーク遅延やバックグラウンドタブの処理制限による数十ms以上の表示差はあり得る。結果パケット未着時は「結果を確認中」と表示し、予測結果を出さない。途中参加・再接続時は抽選スナップショットから現在の段階へ追いつく。

ホスト切断時も抽選は進む。リセット、設定への移行、ゲーム終了では残りのタイマーを取り消す。確定済み番号を取り消す操作はリセットだけ。reduced motion は位置・色を固定し、360ms以上の間隔で数字を更新する。通常は60ms間隔から徐々に減速する。どちらも溜めの間は最後の装飾数字を保持し、サーバーの結果公開時刻は変えない。

## 検証

- `npm run build`
- `npm test`：独立サーバーで既存の参加・復帰・当選テストと、複数ホスト／投影、結果の秘匿、途中参加、切断復帰、繰り返し、リセット・設定への中断を検証。実際の演出時間を使うため数分かかる。
- `PORT=3301 NODE_ENV=production HOST_PASSWORD='' node server/index.js`
- 別ターミナルで `BINGO_BROWSER_URL=http://127.0.0.1:3301 node tests/draw-browser.mjs`。Playwright と Chromium が必要（本クラウド環境では導入済み）。本番サイトを指定しないこと。このスクリプトは指定したローカルサーバーのゲームを操作・リセットする。

ブラウザ検証は司会者 390px、投影 1920×1080、reduced motion 投影 390px、320px の横幅、ホスト時計 +1時間、複数投影・途中参加、接続復帰、リセット、コンソールエラー、履歴の先行表示を対象とする。画像と計測ログは `/tmp/bingoex-*.png` と `/tmp/bingoex-browser.log` に保存する。

## 公開時

フロントとサーバーを同じリリースで更新し、司会者・投影画面を再読み込みする。古いクライアントは共有演出を解釈できない。サーバーは既存仕様のインメモリ状態であり、再起動でゲームが消えるため、開催中に更新せずゲーム開始前に配布と動作確認を済ませる。単一プロセスの運用を維持する。

この変更の公開には、別途レビューとリリース作業が必要。PR の作成だけでは本番に反映されない。

## 数字シャッフルの修正

旧実装では `prefers-reduced-motion: reduce` のとき数字全体を「?」へ置換していたため、説明文だけが変わって見えた。この条件をクラウドブラウザで再現・修正した。本番利用端末の設定は取得していないため、利用者の端末でこの設定が有効だったかは未確認。

現在は司会者・投影とも数字を直接更新する。通常表示は1抽選中に35種類、reduced motionは7種類の数字を表示し、減速後は短く保持してサーバーの番号で停止する。装飾数字はサーバー結果から独立し、履歴には追加しない。数字の不透明度を周期的に落とす演出をやめ、抽選中の文字・球の色を固定した。reduced motionでは移動・拡大も停止する。

`tests/draw-browser.mjs` は通常／reduced motionの司会者・投影、計4画面で実際の数字変更を記録・検証する。`tests/draw-shuffle.test.mjs` は数字の範囲、減速間隔、溜めの保持、reduced motionの更新頻度を確認する。

今回の修正後の検証は `npm test` 10/10成功（約194秒）、本番ビルド成功、クラウドブラウザの4画面で通常35種類・reduced motion7種類の数字更新を確認。本番VPSへのデプロイは別途必要。
